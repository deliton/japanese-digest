幻の城「帰雲城（かえりくもじょう/きうんじょう）」は、今から約450年前に起きた巨大地震による山崩れに吞み込まれ、一夜にして跡形もなく消えてしまったという。

今回は、地震被害で消滅した悲運の城「帰雲城」と、帰雲城と運命を共にした城主一族「内ヶ島氏（内ヶ嶋氏）」の埋蔵金伝説について掘り下げていきたい。

帰雲城を本城としていた内ヶ島氏は、白川郷を統治していた飛騨の国人の一族だ。戦国時代には鉱山経営で財を成して、複数の城を持つほどの勢力を築いていたという。

内ヶ島氏の系譜は、確実な部分のみを遡れば室町幕府第3代将軍・足利義満に馬廻衆として仕えた内ヶ島季氏（うちがしますえうじ）にたどり着く。

季氏の子である為氏（ためうじ）が内ヶ島氏当主であった時代に、室町幕府第8代足利義政の命で金銀山の管理・採掘を取り仕切るために白川郷に入り、城を築いて本拠としてから内ヶ島氏による白川郷支配が始まった。

為氏が最初に築いた城は向牧戸城というが、応仁の乱直前の1462年から1464年頃には帰雲城も築かれていたという。

1467年、応仁の乱が発生して為氏は上洛し、京から白川郷に帰れたのは約11年間に及んだ乱の終結後だった。

その頃の白川郷では、飛騨一向一揆を主導し、さらには加賀一向一揆を支援した照蓮寺の元住職・三島将監（教信）が、内ヶ島氏に匹敵するほどの勢力を持つようになっていた。

1475年、為氏はこの事態を重く見て、照蓮寺を焼き討ちにする。

激戦の果てに三島将監は敗北して切腹し、その弟である照蓮寺住職・明教も逃亡の末に自害した。

明教の跡を継いだ明心は、内ヶ島氏と和睦し従属を受け入れた。

為氏の跡を継いだ内ヶ島氏第3代当主の雅氏（まさうじ）は熱心な一向宗徒で、照蓮寺の本山にあたる本願寺とも友好な関係を結んだ。

戦国時代に入ると、内ヶ島氏は当初室町幕府の命令によって始まった鉱山経営を掌握し、そこから財を成して、帰雲城を本城とするようになった。

そして白川郷内にいくつもの城を持って統治するようになり、実質的な白川郷の戦国大名と化した。

ちなみに彼女の本名は分かっておらず、当時の史料にも「冬姫」という名前は確認できません。

では、なぜ「冬姫」と呼ばれるようになったのでしょうか。

その由来と考えられているのが、婚姻について記した「永禄十二年冬姫」「同じき冬姫を給ひて」といった記述です。

一見すると「冬姫」という女性の名前に読めますが、ここでの「冬」は季節を表しており、本来は「永禄12年の冬、姫が嫁いだ」「同じ年の冬、姫を迎えた」という意味だったと考えられています。

つまり「冬姫」は本名ではなく、史料の「冬」と「姫」がつながって読まれたことで広まった呼び名だったのです。

史料で確認できる彼女の呼称は、出家後の院号である「相応院（そうおういん）」です。

「冬姫」という呼び名は近代以降に広まり、明治41年（1908年）刊行の『国史大辞典』などを通じて定着していったとみられています。 その後、多くの伝記や歴史小説でも冬姫の名が用いられるようになりました。

また、信長は子供たちに奇妙丸・茶筅丸など、現代の感覚からすると変わった幼名をつけたことで知られています。

「信長なら『冬だから冬姫』くらいの名づけをしてもおかしくない」

そんなイメージも、冬姫という呼び名が長く疑われなかった一因なのかもしれません。

冬姫が、夫となる蒲生氏郷（がもう うじさと）と巡り会ったのは、永禄11年（1568年）のことでした。

近江の国人・蒲生賢秀（かたひで）が信長に臣従すると、その息子の鶴千代（のちの氏郷）が人質として織田家に差し出されたのです。

信長は鶴千代の才覚を高く評価したとされ、やがて自らの娘を妻として与えることになります。

翌永禄12年（1569年）、氏郷は伊勢大河内城攻めで初陣を飾り、その後に冬姫と結婚しました。

氏郷と冬姫の間には、のちに蒲生家を継ぐ秀行（ひでゆき）らが生まれました。

氏郷は信長のもとで武功を重ね、順調に立身出世を遂げていきます。

command フックと HTTP フックに onFailure: "block" が追加されました。フックが起動できない、タイムアウトする、または想定外の終了コードで終了した場合に、操作を通さずにブロックします。公式ドキュメントの hooks のページでは、多くのフックイベントで終了コード 2 以外は単独ではブロックせず、たとえば stdout が空のまま終了コード 1 で終わると非ブロッキングエラーとして処理が続行されると説明されています。執筆時点では、このページに onFailure の記載はまだありません。

フックを権限やポリシーの判定に使っている方にとって、フック自体が失敗したときに操作を止める側を選べるようになった点が大きいと感じます。

Program Status Protocol（OSC 7501）に対応しました。このプロトコルを実装したターミナルでは、Claude Code が作業中か、ユーザーの応答待ちか、完了したかを表示できます。

複数のセッションを別々のタブで動かしている方は、ターミナルが対応していれば、応答待ちのセッションに気づきやすくなりそうだと感じます。

gateway、Bedrock、Vertex、Foundry が context-1m ベータを拒否する環境で、[1m] モデルのリクエストがすべて失敗する問題が修正されました。Claude Code はベータ指定なしで再送するようになりました。

Bedrock・Vertex・Foundry や gateway 経由で [1m] モデルを指定している方にとっては、リクエストがすべて失敗していた状態が解消される修正だと感じます。
